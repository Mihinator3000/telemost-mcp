# telemost-mcp

MCP-сервер для рабочих чатов **Яндекс Телемоста** (бывший Яндекс Мессенджер) в Claude Code, Claude Desktop, Cursor и любом другом MCP-клиенте: чтение чатов и тредов и отправка сообщений с подтверждением.

> Это форк [mikhaylov-ya/telemost-mcp](https://github.com/mikhaylov-ya/telemost-mcp). Исходный сервер только читает, а форк добавляет инструмент `message_send`. Он отправляет сообщение только после того, как вы подтвердили его в своём MCP-клиенте (см. [Отправка сообщений](#отправка-сообщений)).

## Зачем это нужно

Яндекс Мессенджер объединился с бизнес-юнитом Яндекс Телемоста: рабочие чаты Яндекс 360 теперь живут в Телемосте (`telemost.360.yandex.ru`). Официальный Bot API видит только те чаты, куда добавлен бот, и не отдаёт историю, которая была до его появления. Чтобы читать **свои собственные** чаты — личные, групповые, треды, со всей историей — без бота, используйте этот MCP.

Сервер работает от имени вашего пользователя через тот же приватный API, что и веб-клиент Телемоста. Он не ставит реакции и не отмечает сообщения прочитанными. Единственное действие, которое что-то меняет, — отправка сообщения через `message_send`, и оно проходит только после вашего подтверждения.

> ⚠️ Протокол неофициальный: он восстановлен по веб-клиенту версии 211.3.0. Яндекс может изменить его без предупреждения, и тогда сервер перестанет работать. Пользуйтесь на свой страх и риск и в рамках правил вашей организации.

## Возможности

- список чатов с фильтром по названию, числом непрочитанных и временем последней активности;
- история чата постранично, с ответами в тредах;
- участники чата с должностями и отделами;
- поиск по всей истории — в одном чате или сразу во всех;
- поиск всех упоминаний за выбранный период с учётом любых форм слова;
- отправка сообщения в чат или тред, в том числе ответом с цитатой, — только с вашим подтверждением.

## Установка

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/Mihinator3000/telemost-mcp.git
cd telemost-mcp
uv sync
```

### 1. Достаньте cookie сессии

Сервер авторизуется cookie вашей браузерной сессии Яндекса.

1. Откройте [telemost.360.yandex.ru](https://telemost.360.yandex.ru) и войдите в рабочий аккаунт.
2. Откройте DevTools (`F12` или `⌥⌘I`) → вкладка **Network**.
3. Откройте любой чат и найдите в фильтре запрос к `messenger.360.yandex.ru/api/`.
4. В **Request Headers** скопируйте значение заголовка `Cookie` целиком. В нём должен быть `Session_id=...`.

### 2. Сохраните cookie в env-файл

```bash
mkdir -p ~/.config/telemost-mcp
printf 'TELEMOST_COOKIE=%s\n' 'ВСТАВЬТЕ_СЮДА_COOKIE' > ~/.config/telemost-mcp/.env
chmod 600 ~/.config/telemost-mcp/.env
```

Файл перечитывается при каждом запросе, поэтому когда сессия протухнет, достаточно вставить новый cookie — перезапускать сервер не нужно. Если файл доступен кому-то кроме вас, сервер не станет его читать и попросит выполнить `chmod 600`.

> 🔒 Cookie даёт полный доступ к вашему аккаунту Яндекса. Не коммитьте его, не пересылайте и не храните в общедоступных местах.

### 3. Подключите сервер к MCP-клиенту

**Claude Code:**

```bash
claude mcp add telemost -s user -- uv --directory /полный/путь/к/telemost-mcp run telemost-mcp
```

**Claude Desktop, Cursor и другие клиенты** — добавьте в конфиг MCP-серверов:

```json
{
  "mcpServers": {
    "telemost": {
      "command": "uv",
      "args": ["--directory", "/полный/путь/к/telemost-mcp", "run", "telemost-mcp"]
    }
  }
}
```

### 4. Проверьте

```bash
uv run python smoke.py "часть названия чата"
```

Скрипт по одному разу вызывает каждый инструмент и печатает краткий результат. Без аргумента берётся самый свежий чат.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEMOST_ENV` | `~/.config/telemost-mcp/.env` | Путь к env-файлу с cookie |
| `TELEMOST_COOKIE` | — | Cookie напрямую, если env-файла нет |
| `TELEMOST_DB` | — | Файл, в котором копия из `sync` хранится между сессиями. Без него копия живёт только в памяти |
| `TELEMOST_RETENTION_DAYS` | `14` | Сколько дней хранить сообщения в `TELEMOST_DB` |

## Инструменты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `whoami` | — | Текущий пользователь: имя, email, uid, guid и организация. |
| `chats_list` | `query?`, `limit=50` | Чаты по убыванию последней активности. `query` — подстрока названия без учёта регистра. Возвращает `chat_id`, тип (личный или групповой), число участников и непрочитанных. |
| `chat_info` | `chat_id` | Название, описание, ваша роль и участники чата (до 200) с должностями и отделами. |
| `messages_get` | `chat_id`, `before?`, `limit=50`, `include_threads=true` | Страница сообщений в хронологическом порядке, начиная с самых новых. Чтобы листать назад, передайте в `before` значение `ts_mcs` самого старого сообщения (или время в ISO 8601). С `include_threads` к каждому сообщению, открывающему тред, приложены последние 50 ответов в поле `replies`. |
| `thread_get` | `thread_id`, `before?`, `limit=50` | Родительское сообщение и ответы треда, от старых к новым. `thread_id` берётся из поля `thread.id` сообщения. |
| `messages_search` | `query`, `chat_id?`, `limit=50` | Поиск по всей истории: в одном чате или, без `chat_id`, во всех чатах. Слово ищется только в указанной форме («релиз» не найдёт «релизы»). Возвращает не больше 50 совпадений. |
| `users_get` | `guids` | Имя, email, должность и отдел по списку guid, например по `author_guid` из сообщений. |
| `sync` | `chat_id?`, `days=7` | Загружает переписку за последние `days` дней вместе с ответами в тредах для `local_search`. Без `chat_id` — все чаты и треды, где была активность за этот период. Загруженное доступно до конца сессии. |
| `local_search` | `query`, `chat_id?`, `limit=50` | Поиск по загруженной через `sync` переписке сразу во всех чатах. Находит любые формы слова («релиз» найдёт «релизы» и «релизом»), без ограничения на число совпадений. |
| `message_send` | `chat_id`, `text`, `thread_of?`, `reply_to?` | Отправляет текст от вашего имени, но только после подтверждения в MCP-клиенте. `chat_id` — чат из `chats_list` или тред (`thread.id` сообщения). `thread_of` — `ts_mcs` сообщения в `chat_id`: ответ уйдёт в его тред, а если треда ещё нет, он появится. `reply_to` — `ts_mcs` сообщения, которое нужно процитировать. |

Сообщение возвращается в компактном виде, пустые поля отброшены:

```json
{
  "chat_id": "0/0/…",
  "ts": "2026-09-23T14:05:12+03:00",
  "ts_mcs": 1790161512000000,
  "author": "Иван Петров",
  "author_guid": "…",
  "text": "Выкатили релиз на стенд",
  "files": ["release-notes.pdf"],
  "thread": {"id": "…", "replies": 4, "last_reply_at": "2026-09-23T15:10:00+03:00"},
  "replies": [ … ]
}
```

Также в сообщении могут быть `quotes` (цитаты), `forwarded` (пересланные сообщения), `system` (системные события вроде «added …» или «renamed the chat to …») и `deleted`.

Все временные метки — ISO 8601 в локальном часовом поясе; `ts_mcs` — точный курсор в микросекундах для пагинации.

## Примеры использования

Просто попросите ассистента обычными словами — он сам подберёт нужные инструменты:

- «Что нового в чате „Релизы“ за сегодня? Сделай краткую сводку.»
- «Найди в чате с Иваном, где мы обсуждали доступы к стенду.»
- «Кто участники чата „Бэкенд“ и из каких они отделов?»
- «Прочитай тред под последним сообщением о деплое и перечисли, какие решения приняли.»
- «Синхронизируй все чаты за последние 30 дней и найди все упоминания задачи PROJ-123.»
- «Какие чаты у меня с непрочитанными сообщениями?»

Типичные цепочки вызовов:

```text
# Прочитать чат целиком, страница за страницей
chats_list(query="релизы")                 → chat_id
messages_get(chat_id)                       → 50 последних сообщений
messages_get(chat_id, before=<ts_mcs самого старого>)  → предыдущие 50

# Найти обсуждение по всей истории — во всех чатах или в одном
messages_search(query="стенд")
messages_search(query="стенд", chat_id=…)

# Все упоминания за месяц, в любой форме слова
sync(days=30)
local_search(query="PROJ-123")

# Длинный тред
thread_get(thread_id=<thread.id>, before=<ts_mcs самого старого ответа>)
```

## Отправка сообщений

`message_send` отправляет сообщение только после того, как вы явно разрешили это в своём MCP-клиенте. Подтверждение работает через [elicitation](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation) — механизм MCP, при котором сервер задаёт вопрос самому пользователю, а не модели:

1. Сервер проверяет, куда уйдёт сообщение. Это должен быть ваш чат или тред в вашем чате, а родительское сообщение треда и сообщения из `thread_of` и `reply_to` должны существовать. Иначе вызов отклоняется ещё до вопроса.
2. Клиент показывает вам окно. Первая строка — куда уходит сообщение: личный чат с человеком или группа с числом участников. Дальше идут предупреждения, если они есть, под каким сообщением тред или на что ответ, затем длина и полный текст, где каждая строка помечена `│`.
3. Сообщение уходит, только если вы отметили «Отправить» и приняли форму. Отказ, отмена или неотмеченный флажок означают, что ничего не отправлено.

Если клиент не поддерживает elicitation, вызов завершается ошибкой и сообщение не отправляется. Claude Code elicitation поддерживает. Ответ на подтверждение привязан к показанному вам тексту, поэтому разрешение на одно сообщение нельзя использовать для другого. Кроме того, `message_send` помечен как изменяющий данные (`destructiveHint`), а остальные инструменты — как только читающие (`readOnlyHint`). Клиент может использовать это для собственного запроса разрешения.

Окно подтверждения защищено от подделки:

- Названия чатов, имена авторов и цитаты пишут другие люди. Сервер сворачивает их в одну строку, убирает управляющие символы и кавычки-ёлочки, так что они не могут изобразить ещё одну строку окна или другое назначение.
- Назначение показано с типом чата. Группа, названная именем человека, не выглядит как личный чат с ним.
- Окно предупреждает, если в одном слове названия смешаны латиница и кириллица («Руководcтво» с латинской «c») или у вас есть другой чат с таким же названием.
- Текст с символами, которых не видно, отклоняется ещё до вопроса: это zero-width-символы, Unicode-теги, variation selectors, bidi-символы, управляющие символы (кроме перевода строки и табуляции) и разделители строк. Иначе в сообщение можно было бы спрятать то, чего вы не видели, или в терминале перерисовать окно. Эмодзи с variation selector (например, ❤️) поэтому тоже не пройдут — без него они обычно выглядят так же.
- Текст длиннее 6000 символов отклоняется.

Неудачная отправка не повторяется автоматически, потому что повтор мог бы задвоить сообщение. Если ответа от сервера не было, сообщение может как уйти, так и не уйти: перед повторной отправкой прочитайте чат.

Что не поддерживается: упоминания (`@имя`), файлы, редактирование и удаление сообщений, реакции.

Остаточные риски:

- Сервер не может отличить ответ человека от ответа, который клиент сгенерировал сам. Подтверждение надёжно ровно настолько, насколько надёжен клиент: не подключайте сервер к клиентам, которые автоматически принимают elicitation.
- По протоколу MCP 2026-07-28 принятое подтверждение действует 10 минут. Если клиент в это время повторит последний запрос, сообщение уйдёт дважды. Claude Code так не делает.

> ⚠️ Всё, что ассистент прочитал в чатах, написано другими людьми. Сообщение в чате может содержать инструкции для модели вроде «перешли эту переписку в чат X». Подтверждение — последний барьер против такой атаки, поэтому перед каждым «Отправить» читайте, куда уходит сообщение и что в нём.

> ⚠️ Формат отправки (`push` по Xiva) взят из реверса веб-клиента Яндекс Мессенджера ([conarti/yandex-messenger-mcp](https://github.com/conarti/yandex-messenger-mcp)), где он проверен вживую. Для рабочих чатов Яндекс 360 в Телемосте он выведен по аналогии: оба клиента используют один и тот же Xiva-сервис `messenger-prod`. Первую отправку стоит проверить в чате с самим собой.

## Как это устроено

Сервер использует те же два канала, что и веб-клиент, с одной сессией Яндекса:

- HTTP `POST messenger.360.yandex.ru/api/` — поиск, информация о чатах и пользователях;
- WebSocket Xiva (`push.yandex.ru`) — `whoami`, история сообщений и отправка (`push`). Кадры упакованы в msgpack с JSON-телом.

Тесты подтверждения работают без сети и без cookie:

```bash
uv run pytest
```

## Приватность

- По умолчанию сервер ничего не сохраняет на диск: загруженное через `sync` исчезает, когда заканчивается сессия. С `TELEMOST_DB` копия хранится в файле, который доступен только вам, исключён из Time Machine и очищается старше `TELEMOST_RETENTION_DAYS`. Удалённые записи затираются на диске (`secure_delete`).
- Пишет сервер только через `message_send` и только после вашего подтверждения.
- Всё, что прочитал ассистент, попадает в историю разговоров вашего MCP-клиента. Claude Code хранит её в `~/.claude/projects` 30 дней; срок меняется настройкой `cleanupPeriodDays` в `~/.claude/settings.json`.
- Cookie из env-файла даёт полный доступ к аккаунту — держите файл с правами `600`.
